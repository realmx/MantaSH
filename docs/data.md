# 数据、凭据和文件格式

## 数据目录与版本

| 平台 | 默认目录 |
|---|---|
| macOS | `~/Library/Application Support/app.MantaSH.MantaSH/` |
| Windows | `%LOCALAPPDATA%\MantaSH\MantaSH\data\` |

数据库为 `mantash.sqlite3`，使用 SQLite WAL；运行期间可能存在 `-wal`、`-shm` 文件，检查或备份前先退出应用。Unix 数据目录权限为 0700。`MANTASH_DATA_DIR` 可指定隔离目录供调试和验收，正常使用无需设置；应用不扫描用户 Shell 历史文件。

`Cargo.toml` 的源码基准版本当前是 `1.1.10`，发布包版本以 tag 为准。应用版本、SQLite `user_version` 与连接 CSV 格式彼此独立。

## SQLite、工作区与恢复

`PRAGMA user_version=1` 是当前数据库格式标记：无标记文件（0）可写入标记，其他未知值会被拒绝且原文件保留，应用进入仅本次运行模式。向后兼容的字段新增沿用该标记，破坏性格式变更须另行升代。表按需创建；`records(kind,id,data)` 使用 `(kind,id)` 主键保存 profile、preferences、workspace、history 和 transfer 的 JSON，`trust(host,port,fingerprint)` 保存已确认的主机指纹。

工作区按稳定的标签/窗格 UUID 保存标签顺序、活动窗格与布局树：叶子引用窗格，分支记录方向、比例与两个子节点；仅本地标签最多五个窗格。布局损坏或引用不匹配时回退到单窗格标签，不截断全部会话。连接会话持有资料快照，编辑连接库不会改写运行中的会话；后台布局保存按递增版本拒绝旧写入，正常退出等待最终保存。

工作区始终自动恢复，但本地标签会启动新的 Shell，SSH 标签等待手动重连；编辑草稿和待确认的进程结束操作不跨重启。传输记录保存连接 ID、连接尝试、源目标、字节数、状态及错误，不保存执行进程。重启时仍活动的任务标为中断，不自动续传；重试创建新任务，原失败记录保留。下载期间未知总量保持空值，成功后才按实际字节数记录。

## 凭据

本机密码库由数据目录内的 `credentials-local.sqlite3` 和 `credentials.key` 组成，与工作区数据库和连接 CSV 分离。每个连接 UUID 对应 AES-256-GCM 认证密文；`vault_meta` 保存随机数据库标识（salt）、nonce 等校验元数据。凭据格式以魔数 `MantaSH local credentials` 标识，魔数、数据库标识与连接 UUID 绑定为认证附加数据（AAD），不接受身份不匹配的库。

程序自动生成、读取本机随机 256 位 key，不设主密码，也不调用系统钥匙串。Unix key 文件以 0600 权限原子发布，已有 key 不覆盖；key 缺失或损坏时报告错误，不生成替代 key 覆盖旧凭据。**备份或迁移必须同时保存 key 文件和密文数据库**。能同时读取二者的本机用户也能解密凭据；这不是针对本机账户失陷的隔离措施。

SSH 先验证主机身份，再读取或发送本机凭据。表单中输入的新密码仅在认证成功后写库，失败密码不会覆盖旧值；“仅保存”只保存公开连接资料。用户明确确认导入 CSV 是另一条入口：程序对实际新增或更新且带密码的有效行尝试按连接 UUID 写入加密库，不等该连接实际登录；写入失败不会回滚已保存的公开资料。编辑时后台读取密码，仅在对应表单仍有效且用户未输入新值时回填；克隆资料生成新 UUID，不复制密码。每次写入使用新 nonce、IMMEDIATE 事务及 FULL 同步；数据库和日志只持久化密文。敏感缓冲尽量清零，但不宣称清除了系统或第三方库的所有副本。

## 连接 CSV

导出使用带 UTF-8 BOM 的标准 CSV；导入接受带或不带 BOM 的 UTF-8 CSV。表头严格为五列（顺序可变，不能缺列、重列或添加列）：

```csv
name,host,port,username,password
Development,example.test,22,developer,
```

逗号或换行由 CSV 引号规则转义；导入时剥离 BOM。文件上限为 8 MB；非法表头拒绝整个文件，行级错误单独显示并保留其它合法行。名称、主机和用户名须有效，主机不能包含 URL scheme、斜杠或空白。`example.test` 仅为示例，参见[完整示例](../examples/connections.csv)。

名称、主机（忽略大小写）、端口、用户名都相同时视为重复，同文件内的重复也按此识别。预览默认跳过重复并保留其已存密码；明确选择更新才保留原连接 UUID 并更新资料，新记录分配新 UUID。确认导入后，仅对实际新增或更新且带密码的有效行尝试写入本机加密库，不进入 Profile 字段；合并不会先清空现有连接。

导出默认文件名 `mantash-connections.csv`，不含 UUID；`password` 列取自本机凭据库解密结果，未保存时为空。**导出文件含明文密码，按敏感文件存储、传输和删除。**

## 编码、在线保存与文件权限

终端使用有状态解码器处理跨网络包的多字节字符；切换会话编码不清空旧网格。文件读取支持 UTF-8、UTF-16 LE/BE：Auto 识别 BOM，否则按 UTF-8；编辑器选择的是**保存编码**，无法表示字符时拒绝写入。二进制控制字节、设备、目录不能作为文本打开；符号链接先展示真实目标并要求确认，实际读取时再次验证类型，目录传输/删除不递归跟随链接。

打开文件记录哈希、长度和修改时间供状态展示；重新打开会读取远端最新内容。保存采用最后保存覆盖：外部编辑先保存不会阻止稍后的 MantaSH 保存。写入通过同目录临时文件和替换流程进行，但 SFTP v3 不保证跨服务器统一原子覆盖，仍有并发窗口。替换前原文件临时移至同级 `.mantash-recovery-<uuid>`；成功后清理，失败尝试还原。网络中断可能留下恢复文件，先核对内容和错误提供的路径，**不要批量删除**。

保存/传输的临时文件以私有权限创建；远端覆盖要求保留原权限和所有者/组，否则拒绝替换。Unix 新上传文件沿用源文件普通权限，Windows 新上传保守使用 0600；Unix 新下载文件使用 0600，覆盖现有本地普通文件时保留其权限。不保证复制平台 ACL 或扩展属性。

## 运行时状态与归属

以下状态只驻留当前进程/会话内存，不新增 SQLite 或连接 CSV 字段：

| 状态 | 有效范围与失效条件 |
|---|---|
| 连接库搜索、选中、排序手势和弹窗焦点 | 搜索过滤清理不可见的批量目标；排序成功才保存新的资料顺序 |
| 文件树/列表滚动和选区 | 目录请求、切换、导航或隐藏过滤后拒绝过期与不可见目标 |
| 传输核对阶段、批次 UUID 与选择器回复 | 按原 Owner、会话、目录请求和任务 UUID 过滤；已完成的传输记录另存 SQLite |
| SSH 历史弹窗搜索、滚动与多选 | 各 SSH 标签共享逻辑列表；删除仍按固定记录 UUID 复核，不按同名文本批量误删 |
| Linux 监控趋势、进程/端口筛选与详情 | 断线或主机重启后清空；详情请求和信号按 Owner、请求 ID、PID、启动标识及主机启动标识复核 |
| 窗口原生菜单、弹窗几何、标签拖动、临时还原位置 | 仅正常窗口位置/尺寸、用户设置的工具宽度及最终标签顺序会保存 |

监控趋势最多保留 61 点、约 180 秒；时间乱序忽略，缺失值和超过 6 秒的间隔断线，主机启动标识变化后重置。CPU 与网络速率需两次有效采样，不从缺失值推断零。进程信号发送成功不等于进程退出；原实例退出仍需后续采样确认，最多等待 10 秒，不自动升级或重试。

## 损坏与隐私边界

数据损坏或只读时退出应用，保留原数据库及 WAL，检查磁盘权限；可用独立 `MANTASH_DATA_DIR` 启动确认问题范围，再从有效 CSV 恢复连接资料，勿直接覆盖未核对的原文件。正式日志与 QA 快照不应包含密码、原始键盘输入、用户数据库或密钥。更多排障见[排障文档](troubleshooting.md)。
