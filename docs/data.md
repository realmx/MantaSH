# 数据、凭据和文件格式

## 数据目录与版本

| 平台 | 默认目录 |
|---|---|
| macOS | `~/Library/Application Support/app.MantaSH.MantaSH/` |
| Windows | `%LOCALAPPDATA%\MantaSH\MantaSH\data\` |

数据库为 `mantash.sqlite3`，使用 SQLite WAL；运行期间可能存在 `-wal`、`-shm` 文件，检查或备份前先退出应用。Unix 数据目录权限为 0700。`MANTASH_DATA_DIR` 可指定隔离目录供调试和验收，正常使用无需设置；应用不扫描用户 Shell 历史文件。

`Cargo.toml` 的源码基准版本当前是 `1.1.10`，发布包版本以 tag 为准。应用版本、SQLite `user_version` 与连接 CSV 格式彼此独立。

## SQLite、工作区与恢复

`PRAGMA user_version=2` 是当前数据库格式标记。新空库直接初始化；已知格式 0/1 先校验，再通过 SQLite Backup API 在数据目录生成 `mantash-before-v2-<uuid>.sqlite3`，包含已提交 WAL，Unix 权限为 0600。备份成功后单一事务迁移历史并升代；备份或提交失败不修改旧库，保留备份。未知版本、未知结构、损坏记录和非法身份拒绝打开，原文件保留并明确进入仅本次运行模式。`records(kind,id,data)` 保存 profile、preferences、workspace、history_catalog 和 transfer 的 JSON，`trust(host,port,fingerprint)` 保存已确认指纹。

偏好加载兼容缺失和已移除的字段。新建 SSH 资料固定预填端口 `22`；旧偏好中的 `default_ssh_port` 不再生效，再次保存偏好时不写回。各条 `profile` 自身的端口保持原值，用户可单独编辑；此规则无需数据库升代。

工作区按稳定的标签/窗格 UUID 保存顺序、活动窗格与布局树：叶子引用窗格，分支记录方向、比例与子节点；仅本地标签最多五窗格。损坏布局回退到单窗格标签，不截断可恢复会话。运行中连接保留资料快照。资料、历史与工作区通过同一个 FIFO 元数据队列提交；回执携带请求 UUID 和单调 revision，UI 拒绝旧回执，正常退出等待队列最终保存屏障。

工作区始终自动恢复，但本地标签会启动新的 Shell，SSH 标签等待手动重连；编辑草稿和待确认的进程结束操作不跨重启。传输记录保存连接 ID、连接尝试、源目标、字节数、状态及错误，不保存执行进程。重启时仍活动的任务标为中断，不自动续传；重试创建新任务，原失败记录保留。下载期间未知总量保持空值，成功后才按实际字节数记录。

### 历史目录与迁移

`HistoryItem` 只保存 UUID 与命令；`HistoryCatalog` 的 `items` 保存全局最近使用顺序，`local_ids/ssh_ids` 仅表示两份列表归属，每个 UUID 必须且只能属于一份列表，不允许重复、孤立或缺失成员。命令只去首尾空白，同列表重复复用 UUID 并置顶，保留内部空白、大小写和 Unicode；跨列表同文各有独立 UUID。两列表合计最多 5,000 条，淘汰与删除同步移除成员索引。内容保存为 `kind='history_catalog', id='current'`，不再写来源或时间。

旧历史按 timestamp 降序、同时间 rowid 降序迁移，去空命令和同列表重复，保留最新 UUID；校验后事务删除旧 history 行。备份及 SQLite 空闲页/WAL 仍可能含旧数据，不承诺介质级擦除。旧程序应拒绝格式 2；恢复旧备份须先退出应用，并会丢弃备份后的元数据变更，不自动回写旧字段。

## 凭据

本机密码库由数据目录内的 `credentials-local.sqlite3` 和 `credentials.key` 组成，与工作区数据库和连接 CSV 分离。每个连接 UUID 对应 AES-256-GCM 认证密文；`vault_meta` 保存随机数据库标识（salt）、nonce 等校验元数据。凭据格式以魔数 `MantaSH local credentials` 标识，魔数、数据库标识与连接 UUID 绑定为认证附加数据（AAD），不接受身份不匹配的库。

程序自动生成、读取本机随机 256 位 key，不设主密码，也不调用系统钥匙串。Unix key 文件以 0600 权限原子发布，已有 key 不覆盖；key 缺失或损坏时报告错误，不生成替代 key 覆盖旧凭据。**备份或迁移必须同时保存 key 文件和密文数据库**。能同时读取二者的本机用户也能解密凭据；这不是针对本机账户失陷的隔离措施。

SSH 先验证主机身份，再读取或发送本机凭据。`remember_credentials` 默认开启，并在每次连接尝试开始时固定；关闭后不读取、不写入，已有密码不删除，正在进行的握手策略不变。新密码仅在认证成功后写库，失败密码不覆盖旧值；“仅保存”只保存公开连接资料，编辑表单不预读或回填密码。用户明确确认导入 CSV 是独立入口：对实际新增或更新且带密码的有效行按连接 UUID 尝试写库，不等该连接登录；失败不回滚公开资料。克隆生成新 UUID，不复制密码。每次写入使用新 nonce、IMMEDIATE 事务及 FULL 同步；数据库和日志只持久化密文。敏感缓冲尽量清零，但不宣称清除了系统或第三方库的所有副本。

## 连接 CSV

导出使用带 UTF-8 BOM 的标准 CSV；导入接受带或不带 BOM 的 UTF-8 CSV。表头严格为五列（顺序可变，不能缺列、重列或添加列）：

```csv
name,host,port,username,password
```

逗号或换行由 CSV 引号规则转义；导入时剥离 BOM。文件上限为 8 MB；非法表头拒绝整个文件，行级错误单独显示并保留其它合法行。名称、主机和用户名须有效，主机不能包含 URL scheme、斜杠或空白。

名称、主机（忽略大小写）、端口、用户名都相同时视为重复，同文件内也按此识别。预览默认跳过重复；明确更新时保留原 UUID，新记录分配新 UUID。确认时按数据库最新资料计算合并，资料事务成功后才写密码，事务失败零密码写入；密码首尾空格/Tab 原样保留，空密码不删除旧值。部分密码失败单独报告和重试，重试不重放资料、跳过已删除 UUID；数据库失败保留失败密码供再次重试。

导出包含整个连接库，不受搜索和选区限制，默认文件名 `mantash-connections.csv`，不含 UUID；密码来自本机库，未保存时为空，读取错误则终止导出。同目录临时文件以 Unix 0600 权限写入并同步，再替换目标；失败保留原文件，拒绝符号链接和非普通目标。**导出文件含明文密码，按敏感文件存储、传输和删除。**

## 编码、在线保存与文件权限

终端支持 UTF-8、GBK、GB18030 和 Big5，使用有状态解码器处理跨网络包的多字节字符；切换会话编码不清空旧网格。文件读取时 Auto 识别 UTF-8/UTF-16 LE/BE BOM，否则按 UTF-8；编辑器选择的是**保存编码**，可用 UTF-8、GBK、GB18030、Big5、UTF-16 LE/BE，无法表示字符时拒绝写入。二进制控制字节、设备、目录不能作为文本打开；符号链接先展示真实目标并要求确认，实际读取时再次验证类型，目录传输/删除不递归跟随链接。

打开文件记录哈希、长度和修改时间；重新打开干净文档读取最新远端内容，已有脏草稿、保存中或旧 attempt 文档复用会话内草稿。保存捕获文本、编码和 revision；成功推进已提交基线，期间的新输入继续保持 dirty。X/Esc 收起编辑器，放弃草稿另确认。保存采用后写覆盖，不提供版本合并。临时文件、关闭、替换沿用 SFTP v3 流程，跨服务器不保证统一原子覆盖；替换前原文件移至 `.mantash-recovery-<uuid>`，失败尝试还原。中断可能留下恢复文件，先核对内容和错误路径，**不要批量删除**。

基础格式化是明确的可撤销编辑：后台统一 CRLF/CR 为 LF、清理行尾空格/Tab、补缺失末尾换行，保留缩进、Unicode 和空行，不自动保存。返回时核对文档、revision、文本、选区/滚动及 IME；一个独立编辑事务保留选区方向、合理映射字节位置并支持单次撤销/重做。

文件列表的权限、大小与修改时间取自同次 SFTP 列目录元数据；修改时间是 SFTP v3 的 32 位 Unix 秒数，只在界面按本机时区显示，不写入 SQLite 或传输记录。复制来源固定完整 Owner、路径和类型，同一 attempt 内导航后可粘贴；后端重新验证源/目标、符号链接、特殊文件、目录包含关系及冲突，通过已验证 SSH 会话执行 quoted POSIX `cp -R --`。预检查与复制之间不是原子事务。重命名期间阻止关联路径读取/保存，成功后更新草稿路径、树和剪贴板；独立操作 UUID 的迟到回执不能刷新新目录。

保存/传输的临时文件以私有权限创建；远端覆盖要求保留原权限和所有者/组，否则拒绝替换。Unix 新上传文件沿用源文件普通权限，Windows 新上传保守使用 0600；Unix 新下载文件使用 0600，覆盖现有本地普通文件时保留其权限。不保证复制平台 ACL 或扩展属性。

## 运行时状态与归属

以下状态只驻留当前进程/会话内存，不新增 SQLite 或连接 CSV 字段：

| 状态 | 有效范围与失效条件 |
|---|---|
| 连接库搜索、选中、排序手势和弹窗焦点 | 搜索过滤清理不可见的批量目标；排序成功才保存新的资料顺序 |
| 文件树/列表滚动和选区 | 目录请求、切换、导航或隐藏过滤后拒绝过期与不可见目标 |
| 传输核对阶段、批次 UUID 与选择器回复 | 按原 Owner、会话、目录请求和任务 UUID 过滤；已完成的传输记录另存 SQLite |
| SSH 历史弹窗搜索、滚动与多选 | 各 SSH 标签共享逻辑列表；删除仍按固定记录 UUID 复核，不按同名文本批量误删 |
| Linux 监控趋势、进程/端口筛选与详情 | 断线或主机重启后清空；详情请求和信号按 Owner、请求 ID、PID、启动标识及主机启动标识复核 |
| 窗口原生菜单、弹窗几何、标签拖动、临时还原位置 | 仅正常窗口位置/尺寸、用户设置的工具宽度及最终标签顺序会保存 |

监控趋势最多保留 61 点、约 180 秒；时间乱序忽略，缺失值和超过 6 秒的间隔断线，主机启动标识变化后重置。CPU 与网络速率需两次有效采样，不从缺失值推断零。进程信号发送成功不等于进程退出；原实例退出仍需后续采样确认，最多等待 10 秒，不自动升级或重试。

## 损坏与隐私边界

数据损坏或只读时退出应用，保留原数据库及 WAL，检查磁盘权限；可用独立 `MANTASH_DATA_DIR` 启动确认问题范围，再从有效 CSV 恢复连接资料，勿直接覆盖未核对的原文件。正式日志与 QA 快照不应包含密码、原始键盘输入、用户数据库或密钥。更多排障见[排障文档](troubleshooting.md)。
