# 版本检查与自动更新

MantaSH 在普通启动约 3 秒后异步检查官方 GitHub 仓库 `realmx/MantaSH` 的最新稳定 Release；持续运行时每 24 小时检查一次，网络失败或服务限流后间隔 1 小时重试。检查使用编译时的 `CARGO_PKG_VERSION`，正式安装包由发布 runner 同步为 tag 版本，不能用主分支 `Cargo.toml` 的基准版本推断已安装版本。

自动检查只有在发布版本按语义版本规则高于当前版本，且包含当前操作系统和架构的安装包及校验文件时，才显示“发现新版本”。相同版本、较旧版本、草稿、预发布版本、缺少对应安装包或检查失败均不弹出更新询问。自动检查结果会等待当前弹窗关闭、应用回到前台后再提示，不覆盖主机身份或凭据确认。

## 手动检查

打开“设置”，点击 footer 右侧的“检查更新”（左侧为“恢复默认”）。弹窗先显示检查进度，再显示新版本、未发现适用于当前平台的新版本，或检查失败及具体原因。失败时可点击“重新检查”；关闭或取消返回设置。检查本身不下载也不安装，发现新版本后仍须点击“确定更新”。

如果自动检查正在进行，手动操作显示同一次请求的进度，不重复请求。手动检查可以重新查看本次运行中已取消的版本，不受自动提示抑制影响。检查期间关闭弹窗会使本次请求失效，迟到结果不能重新打开弹窗或覆盖后续检查。

## 用户操作

- 点击“确定更新”后下载当前平台的原生安装包，显示下载进度，并验证 SHA-256。下载完成不等于可以安装，校验和安装预检必须先通过。
- 点击“取消”或按 Esc 放弃本次更新；下载中的取消会中止请求，准备中的过期结果也不能触发安装。同一版本在本次应用运行期间不再自动提示；下次启动可以重新询问。
- 下载、校验或安装准备失败时，当前应用保持打开，弹窗显示原因，可重试或取消。
- 安装前检查在线编辑草稿和活动传输，复用现有保存/放弃/取消确认。取消该确认也会取消更新。工作区保存失败时不退出、不启动安装。
- 工作区保存成功且安装助手完成交接后，应用退出，由助手等待旧进程退出、安装并重新启动。交接期间不能再次确认或取消，避免重复安装。

macOS 使用对应架构的 DMG，Windows 使用对应架构的 Inno Setup 安装器。更新沿用正式发布包的安全属性：macOS 为 ad-hoc 签名、未经公证，Windows 未做代码签名。系统权限或 Gatekeeper/SmartScreen 确认可能仍需用户操作；自动更新不关闭系统安全检查。开发目录里的独立二进制不应作为正式安装目录进行覆盖。

用户数据库、连接凭据及偏好不属于安装包替换目标；本地终端按工作区重新启动，SSH 仍按既有规则等待重连。

macOS 自动安装仅支持 `/Applications/MantaSH.app` 或 `~/Applications/MantaSH.app` 中的正式包，安装父目录必须可写；直接从 DMG、App Translocation、开发目录或非标准位置运行时，预检失败并保持应用打开。Windows 要求当前目录与 Inno Setup 的已注册安装一致，避免覆盖便携副本或任意目录。权限不足时使用正常系统安装方式更新，不绕过权限检查。

安装助手日志位于系统默认 MantaSH 本地数据目录下的 `updates/update-<UUID>.log`，由 `update::log_directory()` 定位。此目录不随 QA 的 `MANTASH_DATA_DIR` 覆盖。日志记录交接、安装结果及失败时保留的暂存位置；助手就绪或进程已启动不能当作安装成功。应用重启后在“关于”或设置中确认版本，并检查工作区。

## 自动化验证

基础检查：

```sh
cargo fmt --all -- --check
cargo test --locked --no-default-features --all-targets
cargo test --locked --lib ui::updates::tests
cargo check --locked --no-default-features --all-targets
cargo check --locked --all-targets
python3 scripts/check_docs.py
```

后端回归覆盖版本比较、平台资源选择、下载大小及校验、HTTP 错误、取消和安装脚本。隔离 HTTP fixture 只存在于测试，正式客户端不接受环境变量指定任意更新源。测试不替换正在使用的 MantaSH 应用。

debug 原生 QA 驱动需要同时指定全新的 `MANTASH_DATA_DIR` 和 `MANTASH_QA_CONTROL`。隔离运行默认不自动访问版本源；发送 `check_updates` 动作可以立即检查正式 GitHub Release，附加 `"manual": true` 则走设置按钮相同的手动路径。快照的 `update` 字段包含阶段、是否手动、候选版本、下载字节数、是否已准备、是否有活动请求和本次已拒绝版本。动作被接受不代表异步检查完成，应等待快照状态变化。

原生提示/取消检查命令（需联网，调试二进制版本应低于最新稳定版）：

```sh
cargo build --locked
python3 scripts/qa_updates_macos.py --binary target/debug/mantash --directory <全新隔离目录>
```

脚本仅检查正式版本元数据和原生弹窗，以程序化 Esc 取消，不确认下载，不调用安装。

## 分阶段验收

| 阶段 | 操作 | 预期结果 |
| --- | --- | --- |
| 检测 | 对版本比较与 Release 选择运行回归；覆盖 `1.1.9 → 1.1.10`、相同/较旧版本及预发布 | 仅较高稳定版本和完整匹配资源产生候选更新 |
| 提示 | 运行较旧的正式安装包；等待检查。先打开设置或主机确认弹窗 | 更新提示显示当前和目标版本，等现有弹窗结束后出现 |
| 取消 | 在更新询问中点取消或按 Esc，再次自动检查同一版本 | 无下载、无安装；同一次运行不重复自动询问该版本 |
| 手动检查 | 在设置点击“检查更新”；覆盖新版本、无适用更新、错误、重复点击和取消后重新检查 | 显示本次检查进度和结果，错误可重试；手动允许查看已取消版本，关闭返回设置 |
| 下载 | 确认更新，观察进度；分别模拟断网、HTTP 错误、损坏数据和取消 | 错误或校验失败不进入安装，取消后迟到结果不能安装，可重试 |
| 安装前保护 | 准备未保存的在线编辑文件或活动传输后确认更新 | 出现现有关闭确认；取消后不退出；保存失败不安装 |
| macOS 安装 | 在隔离测试账户的可写 `~/Applications/MantaSH.app` 中更新；测试账户路径可包含空格/中文 | 旧进程先退出，再替换并重启；“关于”版本变为目标版本，工作区及数据保留 |
| Windows 安装 | 分别使用 x86、x64、ARM64 正式安装目录更新 | 选择匹配架构的安装器，覆盖当前安装位置，等待完成后重启；系统权限提示正常 |
| 安装异常 | 在隔离安装副本测试权限不足、安装器非零退出、重启失败 | 有明确诊断；不能以已启动子进程报告安装成功，macOS 替换失败应回滚 |

Windows ConPTY、安装体验及真实系统安全提示必须在 Windows 实机验收。脚本测试、macOS 原生窗口 QA 和 GitHub Actions 构建不能替代该验收。
