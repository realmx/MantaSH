# 排障与已知限制

先区分构建、真实运行和旧进程：修改源码后须重新编译并退出旧实例；程序化 QA、截图与实机交互的证据不能互代。安装与平台环境见 [macOS](macos.md)、[Windows](windows.md)，当前验收范围见[验收记录](acceptance.md)。

## 构建或窗口无法启动

确认依赖已下载、Rust/C/C++ 工具链可用，且在正常桌面会话运行。macOS GPUI 在运行时使用 Metal；受限制环境可能允许编译却禁止窗口服务，Windows 需要 MSVC 和 Windows SDK。不要删除 `Cargo.lock` 以碰运气更新依赖。macOS 新包首次打开被 Gatekeeper 拦截时，先核对来源，再按[用户手册](user-guide.md#macos-无法直接打开)使用系统“仍要打开”，不要禁用安全检查。

## 本地终端、补全或乱码

macOS 检查系统 `$SHELL` 可执行文件及用户主目录；Windows 检查设置中选择的 Shell 是否仍可用。Shell 选择只影响新建本地会话；若已选 Shell 不可用，新会话会明确报错，不会静默回退到另一个 Shell。启动失败时修正设置或环境后新建本地标签。

终端中的 Tab/Shift+Tab 交给 Shell 或前台程序，表单中的 Tab 才切换控件；没有补全结果时检查 Shell 的补全配置和匹配项。终端乱码先检查会话编码；文件读取独立于终端编码，Auto 识别 UTF-8/UTF-16 BOM，其他情况按 UTF-8 读取，当前没有单独的文件读取编码选择入口。非 UTF-8 无 BOM 文件可先下载并在外部转码；编辑器的编码选项用于**保存**。

## 文件选择或操作与预期不同

文件列表单击单选、Shift 连续选中、Cmd/Ctrl 增减；双击文件夹进入，双击文本打开编辑。选区只含当前可见路径，导航、刷新或隐藏过滤会清理过期目标。操作入口位于 SSH 标签的底部文件面板；没有可见的目录上传入口。

## SSH 无法连接或反复要求密码

核对主机、端口、用户和密码。指纹变化须通过可信渠道核对服务器身份，不能只为消除警告而批准。对于仅提供旧式 `ssh-rsa` 主机密钥、`diffie-hellman-group14-sha1` KEX 或 `hmac-sha1` MAC 的服务器，MantaSH 会在默认算法之外追加这三项兼容算法，等价于 OpenSSH 的旧版兼容配置；其它更弱算法不会启用。握手含身份确认有 90 秒上限，取消/超时后重新连接会产生新尝试，旧回复无效。后台提示需切回相应标签处理。

新密码仅在**认证成功后**自动写入本机加密库，“仅保存”不会记住密码。仍需输入时检查提示是未保存、凭据库读取失败还是服务器拒绝；可手动更正，错误值不会覆盖旧密码。保存失败不会切断已认证终端。CSV 导出会包含解密后的明文密码，须按敏感文件处理。

## 文件读取或保存失败

SFTP 未启用、路径权限与终端不同、文件类型不符或超过 8 MiB 上限均可能导致失败；SSH 终端可继续使用。重新打开文件会读取远端最新内容；保存采用最后保存覆盖，可能覆盖较早的外部修改。断线后先保留草稿，在新连接中重新核对目标。

若错误提供 `.mantash-recovery-<uuid>` 路径，先核对原文件和恢复文件的内容，再人工恢复；不要批量清理。SFTP v3 不保证跨服务器统一原子替换，网络中断仍可能留下恢复文件。

## 传输中断

取消可能保留已完成的目录项目；临时文件按当前任务清理。重启后活动任务显示“中断”，不会自动续传；“重新传输”创建新任务并从头开始，覆盖已有普通文件需再次确认。符号链接和设备文件不会递归跟随。移除历史记录不删除已传文件。

## 没有命令历史

只记录可靠 Shell 事件，不推断原始键盘输入或密码。zsh 使用 preexec，Bash 不覆盖已有 DEBUG trap，PowerShell 依赖 PSReadLine；自定义配置、空格前缀、隐私过滤或其它 Shell 可能不收录。PowerShell 的 MemoryOnly/SkipAdding 决策仍保留。用户主动写进命令行的敏感参数可能进入历史，请自行避免。

## Linux 系统信息不可用

仅 Linux SSH 主机可使用监控；`/proc`、`df`、`ps`、`ss` 缺失或权限不足会显示原因，不作为零值。端口依赖 iproute2 的 `ss`，进程关联也可能受权限限制。断线、采样失败与成功采样但数据为空是不同状态。

## 数据损坏、只读或界面卡顿

退出应用后保留原 SQLite 数据库与 WAL，检查磁盘空间/权限；可用独立 `MANTASH_DATA_DIR` 启动排查，不直接覆盖原数据。密钥丢失或损坏时不能重新生成 key 解密旧库，备份须同时包含 key 和密码库，详见[数据文档](data.md#凭据)。

卡顿报告应写明系统、窗口尺寸、窗格数量、字体、是否持续输出与系统采样状态；先区分网络等待、终端输出和界面交互，不把截图或构建结果当作性能实测。
