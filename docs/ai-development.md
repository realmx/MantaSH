# AI 开发流程

本页是自动化协作者的操作顺序；不可替代 [AGENTS.md](../AGENTS.md) 的工程约束和[贡献指南](../CONTRIBUTING.md)的提交规则。遇到专项任务按[文档索引](README.md)选择功能、数据、架构、视觉、发布或平台说明。

## 阅读与定位

1. 先查工作区状态，区分用户现有改动和本次任务范围；不覆盖、不回滚无关文件。
2. 对照[功能范围](features.md)和[用户手册](user-guide.md)确认外部行为；改数据/认证读[数据契约](data.md)与[架构](architecture.md)，改发布读[发布文档](release.md)。
3. 定位真实 Rust/GPUI 事件和服务边界，区分产品代码、测试 fixture 与平台待验项。

## 修改与验证

- 沿用现有 Rust、GPUI、SQLite 和服务/事件分层。网络、文件、数据库和凭据操作不阻塞 UI；异步结果须按 Owner 和请求 ID 拒绝过期、取消或重连后的回复。
- 不将模拟数据接到正式 UI；新增文字进入 `src/ui/i18n.rs`，可点击控件使用统一包装层。改动用户流程时更新相应文档；复杂公共接口只写必要说明。
- 运行[基础检查](development.md#必做检查)，按风险补针对性测试。原生窗口、无输入 draw、程序化键盘/指针、真实回环网络与平台人工验收分别记录，不以测试请求被接受代替异步完成。

## 交付边界

报告实际修改、验证命令、未执行检查和剩余限制。Windows 实机仍未验收；macOS ad-hoc 包未公证，不能以 Actions 构建或 Homebrew 安装成功冒充 Gatekeeper 放行后的运行验收。不要记录或提交凭据、原始键盘输入、数据库、缓存或临时日志；不得未经授权删除文件或关闭系统安全检查。
